# 06 · 采集质量模型与来源可行性

> 本文记录两件最容易在迁移后失传的事：
> **① 一条内容凭什么被收进来（质量模型）；② 哪些来源真的能抓、哪些不能（可行性实测）。**
> 这两件事都不能靠读代码猜出来 —— 代码里是规则，规则背后的**误判历史**才是关键。

---

## 1. 为什么需要这套模型（问题陈述）

读者的原始反馈：

> 「现有逻辑虽然包含这些判断但是不够完善，甚至有很多资讯和采集的论文等是一看最新或
> 关联就放进来了」「注意避免灌水（比如标题为面经、八股汇总，实际是卖课推广等）」

实测证据（664 条语料）：

| 指标 | 旧逻辑 |
|---|---|
| 只命中 1 个关键词就入库 | **55%** |
| 相关度分数分布 | p25=52.2 / median=56.7 / p75=61.4（门槛 45 **几乎不起作用**） |
| 论文占比 | 62% |
| 算法题占比 | **0.2%（1 条）** |
| 八股占比 | **0.6%（4 条）** |

根因：`freshness` 独占 30 分，而类目匹配每个关键词只有 8 分 —— **"够新 + 沾边"就能过线**。

## 2. 质量模型：两个独立问题

### 2.1 `knowledgeType`（九类）

| 取值 | 含义 | 知识价值分 | 深度半衰期倍数 |
|---|---|---|---|
| `method` | 算法深度解析 / 论文 | 16 | ×4 |
| `coding` | 算法题 / 手撕 | 14 | ×1.5 |
| `interview` | 面经 / 面试 | 14 | ×1.5 |
| `job` | 岗位 / 招聘 | 13 | ×1.5 |
| `fundamentals` | 八股 / 基础 | 12 | ×4 |
| `project` | 框架 / 实现 | 10 | ×1 |
| `other` | 未归类 | 2 | ×1 |
| `news` | 资讯 | **−6** | ×0.4 |
| `opinion` | 观点 / 吐槽 | **−10** | ×1 |

**判定顺序即设计**（`collect.classify_knowledge_type`）：

1. `kind == "job"` → job（来源权威）
2. **标题级明确标记**：面经/挂经 → interview；`[编程题]`/手撕/leetcode → coding；
   `[单选题]`/八股/题库/汇总/基础 → **fundamentals（必须排在 coding 之前）**
3. **来源与 venue**：`peerReviewed` 或 arxiv/hf_papers/s2/openalex/crossref/openreview → method
4. **代码仓库** → project（除非是通用工具，见 `is_generic_tool`）
5. **文本模式**（`KNOWLEDGE_TYPE_RULES`，先 method 后 news 再 interview）
6. 研究类目 + 长摘要 → method；否则 other

### 2.2 评分公式

```
category      = category_evidence(cat_hits)     # 区分度加权，上限 45
knowledge     = knowledge_value(ktype)          # 上表
unclassified  = -12                             # 仅当没有任何关键词命中
freshness     = 22 × 0.5^(age / (halfLife × typeMultiplier))
source        = 12 × sourceTierWeight[tier]
quality       = min(boost×2.2, …)               # peerReview / stars / upvotes / code
content       = min(9, len(summary)/220 × 9)
total         = (Σ) × 1.04（中文）  ，封顶 100
```

**关键点**：`category_evidence` **不是** `8 × 命中数`，而是按区分度计权：

- 通用词（agent / multimodal / llm / benchmark …，即类目自己的名字）→ **5 分**
- 普通词 → 8 分
- 多词词组或中文术语 → **12 分**

> 类目名是最弱证据。这是"单靠一个 generic 关键词不再足以支撑一条目"的实现方式。

### 2.3 证据闸门（入库阶段）

**只有弱材料受约束**。`SUBSTANTIVE = (method, interview, coding, fundamentals, project, job)`
**永不因为关键词少而被拒** —— 这条作用域是被实测逼出来的（见 §4）。

```
ktype ∉ SUBSTANTIVE 时：
    无任何关键词命中        → 拒绝（news / opinion / offTopic 分别计数）
    单命中且是通用词        → 拒绝（计 weakEvidence）
```

## 3. 反灌水闸门 `spam_reason()`

**核心判据**：

```
spam  =  有明确推销信号  且  缺乏实质技术内容
```

**为什么不是"提到卖课就判死"**：代码随想录确实卖训练营，但它产出的是中文最好的免费算法
教程。用"训练营"一词直接判死会删掉最好的来源。**卖东西 ≠ 提到卖东西。**

判定分支（按顺序）：

| 分支 | 条件 | 结果 |
|---|---|---|
| a | 命中 `SELLING_CTA_RE`（扫码/加微信/限时优惠/点击购买/知识星球/代充…） | 若 `len(summary) ≥ 600` 且技术标记出现 ≥6 次 → **保留**；否则拒绝 |
| b | 标题命中 `PRICING_GUIDANCE_RE`（套餐/订阅/怎么接入/价格对比…）且技术标记 <3 | 拒绝 |
| c | `COMMERCIAL_RE` 命中 ≥3 处、正文 <220 字、技术标记 <2 | 拒绝 |
| d | 命中 `SPAM_ONLY_RE`（品茶/海选/技师/贷款/刷单…） | 拒绝 |

**技术标记**（`TECH_PAYLOAD_RE`）：时间复杂度 / 空间复杂度 / 算法思路 / 代码实现 /
示例 / 推导 / 原理 / 为什么 / 实现方式 …

## 4. ⚠️ 已发生过的误判（迁移时最该读的一节）

**每一个都是真实语料上测出来的，且每一个都是"规则看起来合理、实际在删正确的东西"。**

| # | 误判 | 根因 | 修正 |
|---|---|---|---|
| 1 | 真面经「面了一轮Agent岗，我把问过的问题整理成了文章」被拒 | "单一通用关键词"规则套在了所有类型上 | 闸门只作用于非实质性类型 |
| 2 | `huggingface/diffusers`、`mlc-ai/web-llm` 被拒 | README 不像机制论述 | 新增 `project` 类型 |
| 3 | 真八股「4.2.2 银行技术面---技术基础类问题（操作系统）」被拒 | 商业词匹配到**正文任意位置**（正文含"订阅"） | 商业必须是标题级主张，或主导极短正文；技术密度足够一律保留 |
| 4 | 真面经「极兔后端一面」被拒 | 裸词「秒杀」被当促销词，但**秒杀系统设计是经典面试题** | 只匹配"秒杀价/限时秒杀"，不匹配裸动词 |
| 5 | `halfrost/LeetCode-Go`（题解仓库）被判成 fundamentals | 描述含"数据结构与算法"，而 fundamentals 关键词含通用短语 | **非 method 的摘要级判定必须有标题独立支持** |
| 6 | 同一仓库被判成 fundamentals | `\bGo\b`（想匹配 Go 语言）命中标题里的 "Go" | 删除该模式 —— **语言名不能说明内容类型** |
| 7 | 「技术面试基础知识总结」被判成 interview | 含"面试"两字 | 标题含题库/汇总/基础 → fundamentals |
| 8 | `Awesome-Video-Diffusion` 等**论文合集**被判成工具类 | `curated list of` / `awesome-list` 被通杀 | 按**被整理的主题**判断：技术主题的 curated list 保留 |
| 9 | 审计建议删除采集端乐意接受的内容 | `audit_corpus.py` 自维护了一份 `SPAM_AD_RE` 并与采集端**漂移** | 审计改为**直接复用** `collect.spam_reason()` |

> **教训（第 9 条最通用）**：同一个判断出现在两个地方时，它们**一定会漂移**。
> 审计绝不能建议删除采集端接受的内容 —— 单一事实来源是唯一办法。

### 验证口径（改这些规则后必须重跑）

```powershell
python scripts/selfcheck.py                 # 期望 0 错误
python scripts/audit_corpus.py --list       # 逐条读拒绝理由，确认没有真内容
python scripts/collect.py --only <ch> --limit 10 -v   # 真实抓取上的拒绝理由
```

**只跑合成用例不够**。上面 9 条里有 7 条是合成用例测不出来的，必须拿真实语料逐条读判定结果。

## 5. 来源可行性矩阵（实测，2026-10）

| 来源 | 可抓？ | 依据 | 渠道 id |
|---|---|---|---|
| 代码随想录 | ✅ | robots.txt `Allow: /` + 声明 sitemap（563：algo=298/hot100=48/llm=26） | `programmercarl` |
| 卡码笔记 | ✅ | robots.txt `Allow: /` + sitemap（525：llm/* interview/*） | `kamacoder_notes` |
| 卡码网 | ✅ | robots.txt 404（无禁止声明） | 未接（站点为主，题解走 GitHub） |
| GitHub 算法仓库 | ✅ | 公开 API；精选 15 个高星仓库 | `github_algo` |
| 牛客题库 | ✅ | robots.txt 仅禁 /search /nccommon /ab/ab-test-flow | `nowcoder_questions` |
| 牛客讨论区（面经） | ⚠️ 降权 | 需登录才能看具体内容，标题党多 | `nowcoder`（额度 6） |
| **微信公众号（万诺coding 等）** | ❌ | **无公开 API、无 sitemap**；wannuocoding.com/.cn SSL 握手失败，github.io 404，GitHub 无对应仓库/用户 | 未实现 |

### 关于微信公众号（重要，不要假装能抓）

**微信公众号本身没有任何公开接口**，正文也不在搜索结果里。代码随想录 / 卡码笔记之所以能收，
是因为它们**有独立站点**；`万诺coding` 没有可访问的站点，因此**未实现**。

若要收公众号内容，需要下面之一：

1. 你提供文章的直接链接（可做成 `inbox` 手动导入）；
2. 自建 RSS 桥（如 wechat2rss）并给出 feed 地址 —— 注意现成的公共实例普遍不稳定；
3. 有公开镜像的站点。

**不要把"看起来相关"当成"已经收到了"** —— 这条写在这里，是为了避免迁移后被误认为已覆盖。

### 时效口径（读者明确要求）

**题解、八股、算法题不做时效过滤。** 2019 年的 LeetCode 题解今天依然正确，
`knowledgeValue` 与 `freshness` 半衰期已按类型区分（深度 ×4、资讯 ×0.4），
所以"过往内容"能正常累积，而"最新资讯"不会因为新就占位。

## 6. 采集配比（`config/collector.config.json`）

| 键 | 作用 |
|---|---|
| `limits.perChannel` | 每渠道每轮上限 |
| `limits.perCategoryPerRun` | 每类目每轮上限，再乘 `categoryIntakeWeight` |
| `limits.maxNewPerRun` | 单轮新增总量上限 |
| `limits.dropUnclassified` | 未命中任何关键词者不入库 |
| `channelIntakeOverride` | 单渠道覆盖额度（`nowcoder`=6、`programmercarl`=24、`kamacoder_notes`=20、`github_algo`=12） |
| `categoryIntakeWeight` | 类目额度权重（`coding`=2.0、`exam`=1.8、`paper`=0.4、`trend`=0.3） |
| `scoring.minRelevance` | 相关度门槛 |
| `scoring.knowledgeValue` | 知识类型价值分（可覆盖代码默认值） |

**配比调整是数据，不是代码。** 想改采集倾向就改这里，不要改 `collect.py`。

## 7. 自检如何发现"构成失衡"

`scripts/selfcheck.py::check_knowledge_quality` 把"求职类内容偏薄"变成显式告警：

- `coding` 期望 ≥1%、`fundamentals` ≥3%、`interview` ≥5%、`job` ≥3%
- 资讯/观点 >8% 告警（读者明确不要）
- 论文 >70% 告警（提示语料以论文为主）

> **为什么需要它**：在它存在之前，语料里算法题 0.2%、八股 0.6% 却**没有任何断言会注意**——
> 系统只是安静地积累错误的东西。**"构成失衡"必须是可见的错误，而不是沉默的状态。**
